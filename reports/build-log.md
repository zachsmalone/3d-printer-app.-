## Batch B (design specs from reports/design/, decisions from the parent)

Labels as above. **Nothing in Batch B has been tried on a real iPhone/iPad, with VoiceOver/TalkBack/NVDA, with a real camera, or with children or teachers.** axe-core 4.13 ran in Chrome only (desktop Chrome, emulated 390 px), on the states listed per item; WebKit ran the behaviour checks but not axe.

Decisions applied: warm light theme is the default (dark is a footer choice, an OS dark setting does not flip it); no violet gradient; hero "Turn a photo into something you can print." + "Free to use" (never "free forever"); mode name is **Experienced** (stored value stays `expert`); Teacher mode is view-only for now; no nozzle/download numbers for class students or under-13 viewers; Privacy and Terms pages exist (`static/privacy.html`, `static/terms.html`) before the footer links.

### B1/B2 Warm theme + Mode dropdown - `384e672` (tested)
- Two token sets in `style.css` (light default, `html[data-theme=dark]`), `:focus-visible` ring, reduced-motion and forced-colors blocks. `tests/test_b3_theme.py` recomputes WCAG contrast of every token pair in both themes. One stale test (`ui_settings.py`, "field is dark") now checks contrast >= 4.5:1 instead.
- `#modeSel` (Beginner / Experienced / Teacher) replaces the old switch. Teacher needs a signed-in **adult** account; a visitor/teen/class student who picks it stays where they were, gets a non-modal explanation and keeps focus on the select. Teacher = Beginner view + classroom bar (class names, join codes, "students sending files out of ZEIM" state, Teacher tools button) + Teacher notes open. Returning teachers are restored quietly once the server confirms an adult account; without one the saved choice falls back to Beginner ("Back to Beginner mode." is announced only if Teacher was on this session). `tests/ui_mode.py` (Chrome + WebKit).
### B3 Studio home redesign - `9fcad0b` (tested; axe clean in Chrome)
Hero + three-step path (Photo / Preview / Print-ready, ticks AND borders, polite status line), radio groups for Style and Thickness (`input:checked`), plain-word copy ("Make my 3D model", "Pick up where you left off", "Settings ZEIM picked", "Try a sample photo"), viewer `role="img"` with a text alternative and Turn left / Turn right / Reset view buttons (44 px), result `<h2>` that takes focus after a build, history as a real list with a button thumbnail, "Keep exploring" tiles (hidden in Experienced), footer with Rules / Privacy / Terms / Credits and a **Look: Warm/Dark** button (remembered), dialog `<header>`/`<footer>` replaced by `.dh`/`.df` so the page has one banner and one contentinfo, 3-row phone top bar (<= 170 px at 320 px), Experienced-mode fields now have real label links. `tests/ui_home.py`: h1, landmarks, one primary action above the fold, path states, radios + arrow keys, viewer buttons, Send or save opener, Esc focus return, footer links 200 and >= 44 px, themes, OS dark does not flip default, 320/360/390/768/1280 no sideways scroll, reduced motion, keyboard reaches Mode/Account/Settings, axe on empty / built / Send sheet / Experienced / dark / 320 / 1280. Not done: axe on every dialog; 200% zoom; keyboard order beyond the first nine stops; "Teaching with ZEIM" link goes to Learn (not a specific lesson).
### B4 Nozzle it - `bbb59e2` (tested; real screen readers untested)
Every like/heart is the `.nz` button (inline SVG nozzle, `aria-pressed`, name "Nozzle it, N nozzles" with singular / "no nozzles yet" / hidden-count variants, no "0" shown), updated in place (card and dialog stay in sync, focus stays), optimistic with rollback + `#nzStatus` / `#nzAlert`, presses ignored while a request is in flight, sends `{"liked": bool}` (an old client's `{}` still toggles). ### B6 Teacher Live view (view-only) - `ae51565` (tested; no teacher has used it)
What per-student data existed: ticked **steps per lesson** (no timestamps, no "current step" pointer), builds with title + created time, joined time, and canned student requests (including "I need help"). So the roster shows **"Lesson: N of M steps ticked"**, not "step 3 now". Added: a `last_step_at` timestamp on each tick. Roster (`GET /api/classrooms/{code}/live`, owner teacher only, 404 for other teachers / students / anonymous): nickname, lesson + steps ticked, newest model **title only** (passes the text filter, <= 40 chars; no thumbnail, no file name), last activity (last tick, last model or join time), hand. The hand is the existing canned "I need help with my project" request; "Helped" marks it read. Join-order rows never move; "Show students who need help first" is a manual toggle. Polite announcement, ~12 s polling that stops when the window closes, table with column headers, stacks on phones. Students see: "Your teacher can see your nickname, which lesson step you are on, your model's name, and when you last did something. They cannot see your photos here." Tests: `tests/test_b4_live.py` (6), `tests/ui_live.py` (Chrome + WebKit, axe in Chrome). Not built: student lowering their own hand, a choice of several hand notes (only the one existing canned text), free-text notes, per-page activity.
